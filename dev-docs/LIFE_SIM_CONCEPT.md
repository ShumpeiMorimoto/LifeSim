## ピッチ

**現代日本を舞台に、選択が後々まで効く一度きりの人生を、1〜2時間で生き切るテキスト主体のシミュレーション。**

高校で軽音部を辞めた選択が、41歳の同窓会で固有のイベントを生む。病気も破産も離婚も早世も本物の重みで起きるが、文体には逃げ場の笑いと温かさが残っている。画像ファイルは1枚も持たず、画面はすべてコードが描く。

## 確定事項

### 根本分岐（STEP 0 / 2026-06-14）

| # | 決定 |
|---|---|
| 0-1 | **シングル・マルチ両対応**。エンジンはシングルが核、マルチ（並走する人生＝節目で交差）を加算レイヤーとして乗せる。交差イベントはシングル時に自然に不発になる |
| 0-2 | **1プレイの長さ選択可**。全ステージは必ず通る |
| 0-3 | **トーン = リアルな骨格＋随所に笑い・温かみ**。配分は下記「トーンの配分」で **2026-07-27 に改定**（旧: シリアス7:ユーモア3） |
| 0-4 | **テキスト主体＋没入用UIUX**。純テキストではなく画面演出は持つ |
| 0-5 | **死・失敗はリアルに**。病気/事故/破産/離婚/早世を本物の重みで |

### 大枠（2026-07-27 決定）

| # | 決定 | 理由 |
|---|---|---|
| A | **舞台 = 現代日本・等身大** | 今を生きる普通の人生。内輪ネタ枠(6-5)が最も刺さり、共感ベースの笑いと重みが乗せやすい。量産コストも最小 |
| B | **標準の尺 = 1〜2時間で1人生**（約50〜70イベント） | 一座で生き切れる重みとリプレイ欲の両立。マルチ並走にも現実的。30分の短尺は「長さ選択」の選択肢として提供 |
| C | **コアループ = 方針＋イベントのハイブリッド** | 主体性と物語性の両立。詳細は下記 |
| D | **アセットファイル0** | 画像・フォント・音声ファイルを一切持たない。見た目はCSS/SVG、音はWeb Audio合成。素材調達とライセンス管理の工程が消え、完全自己完結リポジトリになる。実例: [Claude-of-Duty](https://github.com/mshumer/Claude-of-Duty) |
| E | **storylet品質管理 = AI足切り→人が全件選別** | Claude下書き量産 → Claude審査員がトーンガイド照合で足切り → 通過分だけ開発者が全件目視・リライト。「人が選ぶ」の魂を維持しつつ、人が読む本数を減らす |

### トーンの配分（2026-07-27 改定）

**日常は笑い、節目は真顔。** 普段のイベントはコメディ中心で、人生を実際に変える節目だけ真顔で描く。旧「シリアス7:ユーモア3」から実質反転するが、**0-5「失敗もリアル」は放棄しない**——落差があるからこそ節目が強く刺さる、という設計。

これを気分でなく**機械的に判定できる形**にするため、storylet は `register` を必ず持つ:

| `register` | 使いどころ | 比率の目安 |
|---|---|---|
| `comic` | **既定値。** 日常の笑い。滑る・空回る・見栄を張る・場違い | 全体の6〜7割 |
| `warm` | 笑いではないが温かい。報われる、誰かが気づいてくれる | 2割前後 |
| `grave` | 真顔。人生を変える節目 | **1〜2割。それ以上増やさない** |

**`grave` を名乗れる条件（機械チェック可能にする）**: 効果が不可逆であること。死・重病・離別・出生・破産・大成功など、`history` に thread を刻むか、`stats` を不可逆に減衰させるもの。「重い話だから grave」は認めない——**その後の人生が実際に変わるかどうか**が唯一の基準。標準尺50〜70イベントなら `grave` は8〜12回に収まる。

**フェイルセーフ**: 健康・事故・死のカテゴリは `grave` を既定とし、`comic` にするには明示指定を要る（逆方向の事故を防ぐ）。

**`register` が演出を支配する。** `comic` なら周辺減光と粒状をOFF、明るく平坦なパレット、速い→間→オチのテンポ。`grave` なら影・縁光・粒状・ゆっくりした間（＝`demos/` の語彙）。storyletに `register` を1つ書くだけで演出系統が切り替わるので、**O(部品数) を維持したままトーンを二系統持てる**。

### アーキテクチャ

**Quality-Based Narrative（Fallen London 由来）。** 状態ドキュメント＋宣言的条件イベント。条件はコードでなくデータ（JSON DSL）で書くので、ビルド時の全数検証と静的到達性解析ができる。詳細は `LIFE_SIM_ANALYSIS.md`。

**「過去の選択が後で効く」はフラグ経由**で配線する。分岐ツリーは作らない（指数爆発するため）。著作コストはイベント数に線形、体験する組み合わせは指数的——自由度の体感だけを最大化する。

### 状態モデルの骨子（STEP 2 収束・成果物化は未了）

- **stats（5種, 0-100）**: 知力 / 体力 / 魅力 / 精神 / 健康。学力と知力は統合。創造性や商才は専用statを起こさず、才能傾向＋趣味フラグ＋知力ゲートで表現
- **resources（無限）**: money / debt。**有限資源（時間・体力ポイント）は状態に入れない**——表計算的UIを避ける。トレードオフはステージ別のイベント枠上限と、選択肢の機会費用（択一ロック）と、加齢で不可逆に減衰するstatsで表現する
- **hidden（非表示）**: luck / karma / health_risk / regret（後悔の澱＝伏線の保存先）/ crisis_*（エリクソン6段階の課題の未解決度をフラットに事前定義）
- **innate（生得）**: talent（成長倍率）/ upbringing（精神の初期値と下限、逆境耐性）。hiddenとは分離する
- **relations**: 母／父／親友／恋人／ライバル／子の**6スロット固定**に深い状態モデル。他は軽量な数値のみ。固定名前空間にすることで、マルチ交差(D-1)の差込口とビルド時検証を両立させる
- **history**: 伏線回収エンジンの正史。節目のみ記録し、thread_id / closed / 機会費用を持つ
- **派生値（非保存）**: 純資産 / 社会的地位 / 魅力度 / 家庭の温かさ / 人生満足度 / 物語的な決着度
- **エンディング8軸**: 統合 / 絶望 / 早世 / 達成 / 破産 / 遺産 / 孤立 / 再生。資産一本では判定しない

### 2モード構想（開発順序は厳守）

| モード | 性格 | 持ち越し |
|---|---|---|
| **「人生」（本筋）** | 一度きり・失敗もリアル・シリアス7:3 | 力を持ち越さない。「記憶のこだま」（既視感の選択肢・出会いやすさ・karma の残響）のみ |
| **「転生」（王朝・覇業）** | 何度も生まれ変わって成り上がる。軽快・痛快 | 力を含む。家督相続で一族の資産・家業・血統倍率が積み上がる |

**★ 開発順序は固定。本筋を完成させてから王朝を加算する。** 王朝モードは痛快で作りやすいため工数が吸われやすく、本筋が未完で終わるのが設計フェーズ最大のリスク。メタ状態は `meta.echo`（本筋）と `meta.dynasty`（王朝）で完全排他の名前空間にし、別セーブとする。

### 演出方針（CPK: Composed Presentation Kit）

**演出の構築コストは O(イベント数) ではなく O(部品キットの大きさ)。** イベントは `present` ブロック（場面・雰囲気・強度・遷移・テンポ・カテゴリ、すべて閉じたenum）を宣言するだけで、エンジンがビルド時に少数の再利用部品から演出を合成し、結果をスナップショット保存する（実行時に生成しない）。

- キットはイベント数と無関係に有界: 場面テンプレ25-30／雰囲気パレット8-10／NPC状態フック／テキスト逐次表示／遷移6／stat差分FX／SEバンク／アークキット
- **特注の作り込みは「%」でなく絶対数25で上限固定**。1000本になっても25のまま
- 没入予算の配分: **テキストのテンポとNPC状態フックが主役**。背景は数の網羅を優先し作り込みは中程度

**実証済み**（`demos/` 参照）。コードだけの一枚絵が成立する条件は**顔を描かないこと**——人物をシルエットにして光・空気・構図で語らせれば絵の巧拙が出ない。髪型・髪飾り・髪色は具体的にできるが、肌の色まで入れると「顔がないこと」が破綻しはじめる。**本筋NPCをどの描き込み段階で出すかは未決**。

**⚠️ キットは現在シリアス側しか無い（2026-07-27 判明）。** `demos/` の視覚言語（シルエット＋縁光＋周辺減光＋粒状、暗いパレット、夜と夕方、遅い間）は邦画の湿った文法そのもので、コメディを乗せられない。**暗くすれば描き込みの無さが影に隠れる**——コード生成で見栄えを出す最短経路がたまたまシリアスだった、という因果。トーン配分の改定に伴い、コメディ側の部品を追加する必要がある:

| 部品 | 中身 | コスト |
|---|---|---|
| **テンポ**（最重要） | 速く流す→一拍置く→オチを一行。`pacing` にコメディ系の値を足すだけ | ほぼタダ。**既にキットにある機構** |
| **コメディSE** | 下降音（ズコー）／針飛び／無感情ビープ／間抜けなポン | 各5行程度。Web Audioの得意分野 |
| **明るいパレット** | 周辺減光と粒状を**OFFにするモード**。昼の教室、蛍光灯のオフィス、深夜のコンビニ、電車、スーパー | 新規。ただし既存の場所は `time_of_day` で流用が効くので、場面テンプレ予算は+30〜40%程度 |
| **動きの誇張** | 揺れ・跳ね・二度見・硬直。**顔が使えないぶん動きで演技させる** | 新規。シルエットでも動きなら笑いが読める |
| **文字の演出** | サイズの跳ね上げ、一語だけ極太、間だけの「……」 | CSSで無料 |
| **小物** | 顔でなく物で笑わせる（四皿目の唐揚げ、間違った名前の名札） | 既存の小物部品の拡張 |

**落差はむしろ武器**。厳粛な構図で撮った馬鹿げた場面（自販機に腕が挟まった男）は、シネマティックな作りだから面白い。

## コアループ

```
ライフステージ開始
  ↓
【方針を選ぶ】この時期、何に注力するか
  例) 学生期: 勉強 / 部活 / 交友 / バイト
      中年期: 仕事 / 家庭 / 健康 / 趣味
  ↓
  ├─ (a) 該当カテゴリのイベント抽選 weight を増幅
  └─ (b) ステージ末モンタージュでの成長に反映
  ↓
【イベント】1ターン = 1イベント。条件を満たす候補から weight 抽選
  ↓
【選択】選択肢2〜4個。効果は stats / resources / flags / relations / history へ
  ↓
  （ステージ内のイベント枠を消化するまで繰り返す）
  ↓
ステージ末モンタージュ → 次のステージへ
```

**主体性は方針選択から、物語性はイベント抽選から来る。** 選択の主役はあくまでイベント内の選択肢で、方針はその出やすさを歪めるレイヤー。BitLife風の網羅的な行動メニューは採らない（表計算的な育成UIに寄るため）。

**尺の選択（D-2 確定）**: ステージ内のイベント枠数と年齢の刻みを両方スケールさせる。短尺でも全ステージを必ず通るので「一生を生きた」感は保たれる。

**イベント経済の目安**: 標準尺で1人生あたり50〜70イベント消化。プールは最低200〜300本、理想500本超。ライフステージ6区分（エリクソンの発達段階と整合）× 各25〜40本 ＋ 共通・レア枠。

## スコープ外（「これはやらない」）

- **実行時のライブAI生成**。AIはビルド時のみ。検証不能・コスト・トーン制御の喪失・「10,000杯のオートミール」問題
- **OpenAIの使用**（恒久ルール）。AI生成はClaude
- **3D・アクション性**
- **課金・ガチャ導線**
- **BitLife風の網羅的な行動メニュー**（表計算的育成UIの回避）
- **時代・生まれ年の選択**（1960年代生まれ等）。コンテンツが時代×イベントで膨張するため。将来拡張の候補としては保留
- **多言語対応**（当面）
- **手描き・外部調達のアセット**（当面。CPKで足りない判断が出たら再考）
