# 人生シミュレーション リファレンス分析（STEP 1 成果物）

> 作成: 2026-06-14 ／ 親文書: `LIFE_SIM_DEV_PLAN.md`
> 目的: 既存作を解剖し、本ゲームの状態モデル(STEP 2)・イベントスキーマ(STEP 3)・コアループ(STEP 4)の判断材料を作る。
> 前提（STEP 0 確定）: 両対応(シングル核＋マルチ加算) / 長さ選択可 / テキスト主体＋没入UI / 失敗もリアル / トーン=リアルな骨格＋随所に笑い・温かみ。

---

## 0. 最大の結論（先に）

**本ゲームの中核アーキテクチャは Fallen London の「Quality-Based Narrative (QBN)」一択。** 我々が会話で独自に辿り着いた「状態ドキュメント＋宣言的条件イベント」は、QBN の再発明だった。つまり**正しい方向**であり、しかも QBN には10年以上運用された設計パターンの蓄積がある。これを教科書として使う。

QBN の用語対応:
| Fallen London | 本ゲーム | 役割 |
|---|---|---|
| **Quality**(数値/状態変数) | stats / resources / flags / relations / hidden | プレイヤー状態 |
| **Storylet**(条件付きコンテンツ) | event | 条件を満たすと出現するイベント |
| **Opportunity Deck**(機会カードの山札) | イベント抽選プール | ランダム性の源 |
| **Progression Quality**(進行度) | flags(連鎖シリーズの段階) | 「過去の選択が後に効く」配線 |

---

## 1. BitLife — 「年齢=1ターン」のテンポと運の当て方

**解剖:**
- **ステータス4種**: Happiness / Health / Smarts / Looks（各0-100%）。極小セットに絞ることでUIが破綻せず、毎ターンの変動が読みやすい
- **1タップ=1歳**。テンポが速く、20-30分で一生が終わる→死んだら別人生で再生（リプレイ前提）
- **ランダムイベント**は病気・家族・金銭危機を不意に差し込む。ただし完全な無差別ではなく **Karma(隠しパラメータ)が良/悪イベントの確率を歪める**
- **出生時ステータスはランダム生成**（生まれの不平等＝人生の出発点の差をそのまま表現）
- **エンディング=死亡時の称号(Ribbon)**。資産一本でなく「どんな人生だったか」のラベル

**本ゲームへの示唆:**
- ✅ **ステータスは絞る**。BitLifeの4種は少なすぎるかもしれないが、「10種で破綻」より「5-6種で機能」を狙う。STEP 2-1 の指針
- ✅ **Karma=隠しパラメータが運を歪める**は我々の `hidden.karma/luck` 構想と完全一致。「なぜか自分だけ事故る」のドラマはここから
- ✅ **出生ランダム**を採用すれば、リプレイのたびに違う出発点＝自由度の体感が増す
- ✅ **評価軸は多元**（資産だけでなく幸福/達成/人間関係）。STEP 4-5 のエンディング設計に直結
- ⚠️ BitLifeは選択の「重み」が薄い（多くがフレーバー）。我々は0-3トーン的に**選択がちゃんと効く**方に寄せる

## 2. Alter Ego — ライフステージ構造と「テキストで没入」の証明

**解剖:**
- 心理学者(Peter Favaro博士)製。**発達心理学(エリクソンの心理社会的発達段階)ベース**
- **胎内から始まり、幼児→子供→十代→青年→成人→中年→老年**とライフステージを通過。各ステージで出る場面(scenario)が変わる
- ステージごとにアイコン化された「経験」を選ぶツリー。アイコンの種類(♥=感情的な出来事 等)で何系のイベントか分かる
- 1986年の作品が**テキスト主体で今も語り継がれる没入**を達成＝0-4(テキスト主体)判断の歴史的裏付け

**本ゲームへの示唆:**
- ✅ **ライフステージで出現イベントを切り替える**構造はそのまま採用（STEP 4-3）。`stage` フィールドはQBNの大きな progression quality として機能
- ✅ **イベントのカテゴリ可視化**（感情/仕事/健康/お金…のアイコン）は没入UI(D-3)の安価で効く一手
- ✅ 発達段階の「各時期に固有の課題」（幼少期=信頼、青年期=アイデンティティ、中年=次世代育成…）は、**ステージごとのイベントテーマの骨組み**として流用できる。リアルさの裏打ちになり、トーン0-3とも合う
- ✅ テキスト主体で没入できる証明。我々の0-4は安全

## 3. Fallen London / StoryNexus — ★本ゲームの設計図そのもの

**解剖（再利用すべき設計パターン）:**

1. **Quality-Gating（条件ゲート）**: storyletの分岐は quality 値で「選択可/ロック/完全非表示」を切替。→ 我々の `if` 条件DSL。**非表示**も重要（条件を満たさない選択肢は存在自体を隠すと、満たした時の発見が嬉しい）
2. **Opportunity Deck（機会デッキ）**: 引くイベントは山札からのドロー。**チャンスと意図の混合**——プレイヤーは確率を完全制御できないが、状態を整えて引きを寄せられる。→ STEP 4-2 抽選アルゴリズム
3. **Progression Quality（進行度クオリティ）**: 「step 1→4→10→X で別storyletが出る」連鎖。→ **「過去の選択が後で効く」の正体**。我々はフラグ(例 `biz.startup_lv`)で実装
4. **Straight Choices**: 進行度に沿った直線ストーリー（branch-and-bottleneck）。重要な人生節目（就職・結婚）はこれ
5. **Must Sequences（強制連続）**: 逃げ場のない連続storylet。**高リスク・高強度の山場**用。→ 重病・破産・大事故など「リアルな失敗」(0-5)の演出に最適
6. **Wheels（ホイール）**: 専用デッキに閉じ込められ、完了orペナルティまで出られない区画。→ 「受験期」「闘病」「子育て」のような**一定期間プレイヤーを縛るライフフェーズ**に流用
7. **Montage（モンタージュ）**: デッキの反復ドローで「長期間の試行錯誤・成功と失敗の積み重ね」を表現。→ **修行/キャリア/トレーニング期間**を退屈にせず圧縮
8. **Consequence Integration（結果の波及）**: 悪い結果が将来のドローを悪化させる（例: 問題児を選ぶと後で問題イベントが増える）。→ **選択が後に効く**を抽選レベルで実装する手段。`hidden.health_risk` を上げる喫煙フラグ等

**本ゲームへの示唆:**
- ✅ 上記8パターンは **STEP 3(イベントスキーマ)と STEP 4(抽選)の設計言語**になる。スキーマは少なくとも「単発抽選イベント / 進行度連鎖 / 強制連続 / ホイール区画」の4類型を表現できる必要がある
- ✅ **「非表示ロック」をDSLに入れる**（条件を満たさない選択肢を hide するフラグ）
- ⚠️ Fallen Londonはグラインド(反復作業)が冗長になりがち。我々は尺選択(0-2)があるので、**モンタージュは短くテンポよく**圧縮する

## 4. Princess Maker — 隠しパラメータと多重エンディングの育成設計

**解剖:**
- **週単位で時間を配分**して能力を育てる(スケジュール育成)
- **隠しステータス**(母性 等)が終盤まで明かされず、エンディングを左右。PM2は**74エンディング**、PM5は各エンドに明確なステータス要件(魅力≥775 等)
- **トレードオフ**: 「ある値を上げると別の値が下がる」＝資源配分のジレンマ
- 上限の違う数値(999系/100系)を使い分け

**本ゲームへの示唆:**
- ✅ **隠しパラメータが終盤に効く**は再度の確証（hidden枠の価値）。STEP 2-5
- ✅ **多重エンディング＝ステータス要件**の方式は、終了条件(STEP 4-5)を「資産一本」でなく多軸にする具体手段。「学者エンド: 知力≥X」「孤独死エンド: 関係総和≤Y」等
- ✅ **トレードオフ設計**（時間・体力は有限、何かに振れば何かが犠牲）は「選択に重みを持たせる」核。我々のリソースに `time/体力` の有限資源を入れるか検討材料（STEP 2-2）
- ⚠️ スケジュール育成は数値管理ゲーに寄る。我々はテキスト物語主体なので、**育成は「選択の蓄積」で表現**し、表計算的UIにはしない

## 5. Reigns — 「二択×状態変化」の極限ミニマル

**解剖:**
- スワイプ左右の**二択**のみ。4つのメーター(教会/民衆/軍/金)が選択で増減
- **どれか1つでも満タンor空になると死ぬ**＝全リソースの綱渡り
- カードは状況、選択は2つ、効果は4メーターへの増減。極限まで削った QBN

**本ゲームへの示唆:**
- ✅ **「選択の重み」は選択肢2-3個でも十分出せる**。選択肢を増やすより、**効果の明快さ**が重み。我々のchoicesは2-4個で良い（量産コストも下がる）
- ✅ **メーターの両端が死**＝失敗のリアルさ(0-5)を仕組みで表現する一案。健康0で死、借金過大で破産エンド、メンタル0で別の悲劇
- ⚠️ Reignsは物語の深みより回転の速さ重視。我々はテキスト没入側なので、ミニマルさは**抽選の軽さ**に活かしつつ本文は厚く

## 7. この分析が STEP 2 に投げかける問い（開発者が決める）

リファレンスから、STEP 2(状態モデル)着手前に開発者が答えると良い問い:

1. **ステータスは何種か・何を測るか**: BitLifeの4種は少ない。候補は 知力/体力/魅力/メンタル/健康 の5種前後。「学力」と「知力」を分けるか等、粒度の判断
2. **有限資源(時間/体力)を入れるか**: Princess Maker型のトレードオフを入れると戦略性が増すが、テキスト主体のテンポと両立するか
3. **隠しパラメータの種類**: luck / karma / health_risk は確定的。他に「才能」「育ちの良さ」等の生得値を入れるか
4. **人間関係の粒度**: 個別エンティティ(母/親友/恋人)を何人まで状態に持つか。多いとマルチ交差(D-1)が豊かになるが管理が増える
5. **エンディングの軸**: 何で「どんな人生だったか」を判定するか（資産/幸福/達成/関係/称号の組合せ）

## 8. ★アーキテクチャ分岐: NPCの状態モデル化とAI生成（2026-06-14 提起）

開発者アイデア:「ユーザーだけでなく**全登場人物に状態モデルを付与**し、それを入力にAIがその人物・状況に合った発言を生成する。登場人物をデータとして深掘りすればよりリアルになる」。

参考: スタンフォード **Generative Agents (Smallville, 2023)** = 記憶/反省/計画を持つAIエージェントの自律生活。研究グレード・LLM呼び出し数千回・高コスト。本案のフル版が向かう先。

**核とフル版を分離して評価:**
- **核(NPCを状態モデル化)= 即採用**。NPCに `health/mood/money/flags/history` を持たせ、storyletが条件・本文で参照。リアリティ7割をコスト5%で。Fallen Londonの仲間NPC方式
- **フル版(ライブAIが全発言生成)= 問題多数**: (1)QBN(検証可能な手書き背骨)と衝突 (2)実行時コスト/レイテンシ(OpenAI禁止・友達反復プレイ・テンポ死) (3)トーン制御喪失(0-3で慎重に決めた) (4)「10,000杯のオートミール」=多様だが無意味

**採用方針(ハイブリッド) — このプロジェクトの「ビルド時AI生成→静的配信」パターン(事前クイズセット/事前TTS)を流用:**
| 層 | 中身 | 性質 |
|---|---|---|
| 状態層 | 全(主要)NPCに状態モデル | 安い・即採用 |
| コンテンツ層 | storyletがNPC状態を参照。**AIはビルド時**に「アーキタイプ×状態バケツ×状況」で条件付きセリフ群を量産→開発者選別→コミット | 実行時0コスト・検証可能・トーン保証。「AIが書く・人が選ぶ」方針通り |
| (任意)化粧層 | 将来: 効果/フラグは手書き決定論、AIは表面文だけ状態適応で差替、失敗時は手書きにフォールバック | コスト/トーンを封じ込めた色付け |

**プロジェクトの分岐として明示:**
- Path A 著作シミュレーション(QBN＋NPC状態参照) = 検証可能/トーン制御/今設計したもの ← **推奨ベース**
- Path B 生成シミュレーション(エージェント＋ライブAI) = 創発的/無限だが高コスト/検証不能/研究グレード別プロジェクト

**推奨: A ＋ NPC状態モデル ＋ ビルド時AI生成（必要なら封じ込めた化粧層）。** 内輪ネタ(NPCに友達アーキタイプ)とも好相性。

**STEP 2 に追加される開発者判断**: NPCをどこまで深く状態化するか — 母/親友/恋人/ライバル等、何人を「自分の弧を持つ存在」にするか（管理コストとマルチ交差D-1の豊かさのトレードオフ）。
