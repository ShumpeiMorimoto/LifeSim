## 恒久メモ（＝再調査するな。確定済みの判断）

- **QBN一択**。「状態ドキュメント＋宣言的条件イベント」は Fallen London の QBN の再発明であり、正しい方向。分岐ツリーは作らない（指数爆発）
- **有限資源（時間・体力ポイント）は状態に入れない**。表計算的な育成UIを避けるため。トレードオフはイベント枠上限・選択肢の機会費用・加齢による不可逆減衰で表現する
- **ライブAI生成は背骨にしない**。検証不能・コスト・トーン制御の喪失・「10,000杯のオートミール」問題。AIはビルド時のみ
- **開発順序は「人生」モード完成→「転生」（王朝）モード**。王朝は痛快で作りやすいぶん工数を吸うので、本筋が未完で終わるのが最大のリスク
- **コードだけで絵が成立する条件は「顔を描かないこと」**（`demos/` で実証）。髪型・髪飾り・髪色は具体的にできるが、肌の色を入れると顔がないことが破綻しはじめる
- **トーンは「日常は笑い、節目は真顔」**（2026-07-27改定）。`grave` は効果が不可逆なものだけで1〜2割。「重い話だから grave」は認めない
- **暗い演出はコード生成の逃げ道**。影が描き込みの無さを隠すので、放っておくと自然にシリアスへ寄る。デモ3本が3本とも湿ったのがその実例。**明るい側は意識して作らないと生えてこない**
- **演出コストは O(部品数)**。1イベント1演出の手作りは禁止。特注 set_piece は「%」でなく**絶対数25**で上限固定
- **トークン節約は常時の要件**。上限に余裕があることは雑に使ってよい理由にならない。割り当ては `LIFE_SIM_DEV_PLAN.md` 付録E
- **見積もりは推定でなく実測から**（`/usage` の増分を線形外挿）。2026-07-27に推定で答えて1桁外した
