# Documentation Consistency Checklist

Documentation drifts faster than code. Most reviews catch code issues but skip docs entirely. Scan documentation files explicitly — they shape how new contributors (and future-you) understand the project.

## What to scan for

### 1. Stale references to deleted code
The most common doc bug. After a refactor or removal:

- File names mentioned in docs but no longer in the repo (e.g., `predict_universal.py`)
- Directories listed in project structure but deleted (e.g., `models/universal_hub/`)
- Functions/classes referenced in examples but renamed
- Scripts in "Scripts Reference" tables that no longer exist
- Mermaid/ASCII diagrams showing the old architecture

**Detection**:
```bash
# For each file/symbol mentioned in docs, verify it exists
grep -roh '`[a-zA-Z_/.]*\.\(py\|jsx\|js\|ts\|md\)`' *.md dev-docs/ | sort -u | \
  while read ref; do
    path=$(echo "$ref" | tr -d '`')
    [ -e "$path" ] || echo "MISSING: $ref"
  done
```

### 2. Architecture drift
Docs that describe a different architecture than the code:

- "Two-stage Universal + Specialist" when code is now LightGBM-only
- "Express Node.js server" when backend migrated to FastAPI
- "src/" structure when renamed to "frontend/"
- Layer descriptions that don't match current import structure

**How to spot**: Read the high-level architecture section, then grep the actual code for the claimed structure. Mismatch → finding.

### 3. Outdated commands
Commands in setup/training/dev guides that no longer work:

- `python xxx.py` when entry is `python -m xxx`
- `npm run dev` when the script was renamed
- Hardcoded `.venv/Scripts/python.exe` (Windows-only) when project moved to `uv run`
- PowerShell-only commands (`cmd /c ...`) in cross-platform docs
- Old env var names

**Detection**: For each `bash`/`shell`/`powershell` code block in docs, check the command exists in `package.json` scripts or as a runnable module.

### 4. Performance numbers and benchmarks
Hardcoded statistics that go stale:

- "Top-5 hit rate: 64.4%" when retraining produced different results
- "250-day backtest: +43%" when the backtest date range moved
- "Training takes 15 hours" when GPU/algorithm changed
- "5,000 trades parsed in 2 seconds"

**Approach**: Note the date the metrics were measured. If the doc has no date, request one. Unless the metric is currently regenerated by CI, treat any number as potentially stale.

### 5. TODO and FIXME with no follow-up
- `# TODO: refactor this later` from 2 years ago
- `# FIXME: works on prod, broken in dev` (broken thing now broken in prod too)
- Roadmap sections listing "Phase 4" forever
- "Coming soon" features that shipped (or never shipped)

### 6. Inconsistent terminology
Same concept, different names across docs:

- "AI Lab" vs "ML Lab" vs "Predictor"
- "trade pairing" vs "matching" vs "linking"
- "Direction model" vs "Classifier" vs "Binary model"
- Frontend/backend naming for the same API field

**Pick one term per concept and stick to it.**

### 7. Broken cross-references
- Links between docs that point to renamed files
- Anchor links (`#section-name`) that no longer exist
- Image references missing files
- Code links pointing to wrong line numbers

### 8. Missing sections for new features
A new feature was shipped but no doc updated:

- New API endpoint not in `routers` table
- New env var not in `.env.example`
- New script not in `scripts/` reference
- New directory not in project tree
- New dependency without rationale

**Detection**: Compare git log of recent commits against doc modification times. If `git log --since=30days backend/intraday/` shows commits but no doc files changed, that's a finding.

### 9. Setup instructions that don't reproduce
Try to follow the setup section as if you were a new contributor. Things that often break:

- "Run `npm install`" when only `pnpm` works
- Missing prerequisites (Python version, OS-specific tools)
- Env vars marked optional that are actually required
- Commands that require manual prior steps not documented

### 10. Out-of-sync schema descriptions
- DB schema described in docs differs from actual `CREATE TABLE` statements
- API response shape in README differs from actual handler return
- Frontend prop docs differ from actual component signature

## Where to look

Cast a wide net for documentation. Common locations:

- **Root**: `README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `ARCHITECTURE.md`
- **Project rules**: `CLAUDE.md`, `.cursorrules`, `AGENTS.md`
- **Subdirs**: `backend/README.md`, `backend/ml/README.md`, `frontend/README.md`
- **Dev docs**: `dev-docs/`, `docs/`, `documentation/`, `wiki/`
- **Inline**: Module docstrings, especially top-of-file comments
- **Examples**: `.env.example`, `config.example.*`
- **Templates**: `.github/PULL_REQUEST_TEMPLATE.md`, `.github/ISSUE_TEMPLATE/`
- **Skill files**: `.claude/skills/*/SKILL.md` and references

**Critical**: Run `find . -name "*.md" -not -path "*/node_modules/*" -not -path "*/.git/*" -not -path "*/.venv/*"` early in Phase 1 to enumerate all docs. **This is the step that prevented `dev-docs/` from being missed in past reviews.**

## Detection strategy

1. **Enumerate all .md files** at the start of Phase 1 (not just `README.md` and `CLAUDE.md`)
2. **Read the architecture section** of each doc — compare against current source structure
3. **For each file/module name in backticks**, verify the file exists
4. **For each command in code blocks**, verify it's runnable
5. **Check `git log --diff-filter=D --since=60days`** for recently deleted files — grep docs for those names
6. **Check `git log --since=30days`** for new files — grep docs for those names
7. **For each env var in `.env.example`**, grep source for its usage
8. **For each script in "Scripts Reference" tables**, verify the script file exists

## Output format

```markdown
## Documentation findings

### Stale references (P1)
- `dev-docs/STUDY_GUIDE.md:120` — references `predict_universal.py` (deleted in commit abc123)
- `dev-docs/STUDY_GUIDE.md:155` — Mermaid diagram shows `MLPredictor.jsx` (renamed/deleted)

### Architecture drift (P2)
- `README.md:23` — claims "PyTorch Universal Transformer" but code is LightGBM-only
- `dev-docs/TIPS.md:55` — "Legacy: Universal Transformer (PyTorch)" — should be removed entirely

### Outdated commands (P2)
- `dev-docs/TRAINING_GUIDE.md` — uses `powershell` code blocks; project is now bash on all platforms via `uv run`

### Missing for new features (P2)
- `CLAUDE.md` — no mention of `backend/intraday/` (added 2026-04-05)
- `CLAUDE.md` — no mention of `backend/auth.py` and API_SECRET_KEY env var

### Stale benchmarks (P3)
- `README.md:14` — "5-day model: ~68% accuracy" — undated, last measured?

### Broken cross-references (P3)
- `dev-docs/STUDY_GUIDE.md` TOC — anchor `#ai-architecture` removed but TOC still references it
```

## Why this matters

Stale docs cost more than no docs:
- New contributors trust the doc, write code based on the wrong mental model, then need rework
- Future-you reads your own old doc and chases ghosts
- AI assistants (including this one) load stale docs as ground truth and propagate the drift

Treat documentation as code: it should be reviewed, kept tested, and refactored alongside the source.
