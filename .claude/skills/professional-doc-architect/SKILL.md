# Professional Doc Architect (Technical Documentation Excellence)

This skill provides a framework for creating "Master Class" documentation for any codebase, ensuring that it serves as both a reference and a learning tool.

## 1. Structural Layering (The "Mindset" Split)
Regardless of the domain, divide documentation by the nature of the logic:
- **Foundational Core (Deterministic)**: Documentation for the rigid, logical backbone of the system (Databases, PnL calc, Auth, Core APIs). Accuracy and stability are paramount.
- **Extended Logic (Probabilistic/Dynamic)**: Documentation for flexible or complex layers (AI/ML, Recommendation engines, UI/UX flows, Heuristics). Reasoning and expectations are paramount.
- **Integration Layer**: How these parts converge into a single system.

## 2. The "Mathematical Transparency" Standard
For any algorithmic or data-driven component:
- **Latex Formulas**: Express the logic as a formal equation.
- **Variable Dictionary**: Define every symbol (e.g., $P_t$, $\alpha$, $W$) immediately after the formula.
- **Rationale**: Explain *why* this specific math/algorithm was chosen (Performance, Precision, Compatibility).

## 3. Visual Communication (Mermaid First)
Never rely on text alone for complex flows:
- **Architecture Diagrams**: High-level component interactions.
- **Sequence Diagrams**: For full-stack execution flows (UI -> API -> Logic -> DB).
- **Flowcharts**: For complex conditional logic (e.g., Error handling, State machines).

## 4. Progressive Disclosure & Tone Refinement
- **The "Engineer to Human" Pipeline**: Draft the first version with high technical precision. Then, refactor based on the target audience (e.g., "Beginner Developer" vs "Domain Expert") to simplify terminology without diluting facts.
- **Analogy Anchoring**: Use familiar analogies (The Gatekeeper, The Archive, The Predictor) to anchor abstract technical concepts.

## 5. Professional "Real-world" Insights
Always add a section for practical engineering hurdles:
- **Security & Ethics**: Rate limits, data privacy, and safe processing.
- **Robustness**: Handling edge cases, NaN values, or network failures.
- **Optimization**: Scaling considerations and performance bottlenecks.

## 6. Document "Annealing" Process
1. **Scope**: Identify the project's core pillars.
2. **Skeleton**: Build a TOC with jump links for speed navigation.
3. **Execution**: Populate with Math, Code, and Visuals.
4. **Simplification-Loop**: Review and replace overly academic terms with functional, approachable ones until the user (or target dev) finds the document "perfectly balanced."
